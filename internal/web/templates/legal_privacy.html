更新日期：{{.Legal.Updated}}

PlainMote（{{.Legal.Site}}，以下简称“本服务”）{{if .Legal.Operator}}由 {{.Legal.Operator}}（以下简称“我们”）运营{{else}}的运营者以下简称“我们”{{end}}。本政策说明您使用本服务时我们收集哪些信息、如何使用和存储这些信息，以及您享有的权利。

要点

  • 本服务不展示广告，不使用任何分析或跟踪工具，不出售用户信息。
  • 使用 GitHub 登录时，本服务仅读取您的公开资料，不获取邮箱地址。
  • 通过分享链接访问内容时，本服务会记录访问者的 IP 地址和浏览器信息，该记录对链接创建者可见。

一、我们收集的信息

（一）账号信息

您使用 GitHub 登录时，本服务仅读取您的 GitHub 公开资料，并保存您的 GitHub 用户 ID、用户名、显示名称和头像地址。本服务不获取您的邮箱地址、代码仓库或其他 GitHub 数据，也不保存 GitHub 授予的访问令牌。

（二）登录状态

登录后，本服务通过 Cookie 维持您的登录状态。登录有效期为 {{legalDuration true .Legal.SessionTTL}}，退出登录后立即失效。

（三）您存储的内容

包括您创建的资源的正文、名称和文件名等信息（远程资源仅保存其源地址），以及分享链接的备注、有效期、次数上限、使用次数和撤销状态。{{if .Legal.R2}}资源正文存放于 Cloudflare R2 对象存储，并以加密形式保存。{{end}}我们在技术上能够访问上述内容，但仅在排查故障、处理滥用举报或依法需要时查看。

（四）分享链接访问记录

通过分享链接获取内容时，无论请求成功或被拒绝，本服务均会生成访问记录，内容包括访问时间、访问结果、IP 地址、浏览器与设备信息、来源页面以及请求地址等网络请求信息。

访问记录归属于资源所有者，所有者可在“访问记录”页面查看。因此，当您打开他人发送的链接时，链接创建者可以看到您的 IP 地址和浏览器信息。即时通讯软件生成链接预览时发起的请求同样会被记录。

Privacy Policy

PlainMote ({{.Legal.Site}}, the “Service”) is operated by {{if .Legal.Operator}}{{.Legal.Operator}} (“we”){{else}}its operator (“we”){{end}}. This policy describes the information we collect when you use the Service, how that information is used and stored, and the rights available to you.

Key points

  • The Service displays no advertising, uses no analytics or tracking tools, and does not sell user information.
  • When you sign in with GitHub, the Service reads your public profile only and does not obtain your email address.
  • When content is accessed through a share link, the Service records the visitor’s IP address and browser information, and this record is visible to the creator of the link.

1. Information we collect

1.1 Account information

When you sign in with GitHub, the Service reads only your public GitHub profile and stores your GitHub user ID, username, display name and avatar URL. The Service does not obtain your email address, repositories or any other GitHub data, and does not store the access token granted by GitHub.

1.2 Sign-in state

After you sign in, the Service uses a cookie to keep you signed in. A sign-in remains valid for {{legalDuration false .Legal.SessionTTL}} and ends immediately when you sign out.

1.3 Content you store

This includes the body, name, filename and similar details of the resources you create (for remote resources, only the source URL), together with the note, validity period, use limit, use count and revocation status of your share links. {{if .Legal.R2}}Resource bodies are held in Cloudflare R2 object storage in encrypted form. {{end}}We are technically able to access this content, but do so only to diagnose faults, handle abuse reports or where required by law.

1.4 Share link access records

Whenever content is requested through a share link, whether the request is served or refused, the Service creates an access record containing network request information such as the time, outcome, IP address, browser and device information, referring page and requested address.

Access records belong to the owner of the resource, who can view them on the Access history page. Consequently, when you open a link sent to you by someone else, the creator of that link can see your IP address and browser information. Requests made by messaging applications to generate link previews are recorded in the same way.

1.5 Quick shares

Quick shares on the home page can be created without an account. The Service stores the text and filename you submit (or, with end-to-end encryption, only the ciphertext; see the third paragraph of this section). The link expires after at most {{legalDuration false .Legal.AnonymousTTL}}, after which the related content is deleted. The Service does not record the IP address of the person who creates a quick share. A quick share created while signed in is associated with your account: for an unencrypted one, so that you can later save it to your resources; for an end-to-end encrypted one, which cannot be saved as a resource, solely to handle abuse reports.

Access records for quick shares do not belong to any account and cannot be viewed by any user. If the creator saves a quick share to their resources, its existing access records are transferred to that account.

Signed-in users can turn on end-to-end encryption in their account settings. Quick shares are then encrypted in your browser before they are uploaded; the Service stores only the ciphertext and neither stores nor can obtain the key or passphrase needed to decrypt it, so it cannot read, recover or review the content. The size of the content and access record information such as the time of access and IP address are not encrypted and are handled as set out above for quick share access records. The encryption and decryption code is provided by the Service, and its security depends on the integrity of the code the Service delivers{{if .Legal.SourceURL}}; the source code of the Service is published at {{.Legal.SourceURL}} and can be checked{{end}}.
